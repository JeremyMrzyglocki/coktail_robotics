HOW IT BIDS

  1. Demand. Each request whose plan could not run counts toward every skill that blocked it: a gap (no catalog skill does the motion) or an untrained skill (listed, no trained model). The k-th repeat of the same prompt counts 1/k, so one person retrying cannot buy a dataset; distinct requests count fully. Old requests fade with the half-life.
  2. Value. A blocked request is a lost sale worth its whole plan, each gap priced like a typical skill. Every blocker in that plan has to be filled, so each gets an equal share. Each logged request stands for future sales per request sales once the skill exists.
  3. Bid. Spend at most value ÷ target ROI on the skill's data, spread over the episodes it needs. A matching open dataset cuts the episodes needed: it covers pretraining, paid episodes only cover this robot. Capped per episode.
  4. Pacing. If all bids together exceed the monthly budget, every bid is scaled by the same factor, so the order holds: more unmet demand, higher bid.
